A second "may act" rule in the read model will drift from the engine's; a screen's "may" must be the engine's predicate itself, tested at the API beside the screen test that hides the button.

- **What happened (22 November 2026, Phase 4b final review).** The screens added client ownership in `backend/app/squad/rules.py` (an analyst acts only on her own clients), while the engine (`workflow.decision_refusal`) answered only by role. On the seeded book the engine accepted Tomas Keller's decision on Priya Raman's client (Dataflake) while every screen hid the button, and his case view still offered Route and Attach. The same split made officers, portfolio managers and credit administration count every analyst's unassigned case as "waiting for you" (Helen's home said 9, her Approvals 5).
- **Why it hid.** Every screen test passed, because each screen read the same second rule. No test called the API as the person the screen refused.
- **Rule.** Who may decide, route or attach is answered once, in the engine (`workflow.decision_refusal`, which ends with `workflow.owner_refusal`; `routing.route_work_item` and `attach_evidence` call the same rule). The read model (`squad/rules.py`) may add only whose turn it is (assignment, an approver's permission, a return), never who may. "Yours" means at least one offered decision passes the engine's predicate with that decision named, so a decision's own precheck (the last editor of commentary) counts too.
- **How to apply.** For every refusal a screen expresses by hiding a control, write the API test in the same commit: the refused person gets 403 (or 409/422) from the route itself, and the screen test shows no control (see `backend/tests/squad/test_ownership.py` and `frontend/src/squad/__tests__/case.test.tsx`).
- **Moving the rule into the engine moves it for every caller.** The evaluation harness decided every analyst item as one generic "Evaluation analyst"; once the engine owned ownership, it was refused on every client with an analyst and the innovation stand-in gate failed (cycles stopped before signals). The harness now decides as the client's own analyst (`evals/run.py::_decider`). When a rule moves into the engine, grep every caller of `decide_work_item`, not only the screens.
