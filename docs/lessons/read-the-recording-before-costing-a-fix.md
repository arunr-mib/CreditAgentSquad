A handoff's diagnosis of a model failure goes stale; read the recorded exchanges before costing or designing a fix.

What happened: on 24 November 2026 the handoff listed two billable re-records as waiting for the owner. Kestrel Bay's missing recommendation was put down to the Covenant Agent's step cap, and Pellham Grain's wording was said to need a fix. Reading the recordings showed otherwise. Kestrel's agent had finished and answered twice; both answers were withheld because "In Schedule 1" opened a sentence with a capital and the reference rule knew the word only in lower case. Pellham's first answer was refused and its retry passed, so nothing was failing. The step cap had been fixed days earlier. The cost of both "re-records" was nil: one was a guardrail fix proven by replaying the existing recording, the other needed nothing.

The rule: before estimating or approving a billable run to fix an agent's behaviour, open the recorded exchanges for that case, run the product's own check on the final answer, and name the exact text that was refused. If the model's answer is sound and a check refused it, the fix is in code and a replay proves it.

Why: a diagnosis written while a defect was open describes the defect as it was then. Later fixes change the cause without changing the symptom, and a re-record of an unchanged cause buys the same failure.

Where it applies: any item in a handoff or backlog that says a model run is needed to show a fix; any named failure in an evaluation scorecard.
